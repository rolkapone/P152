## Findings

|---|---|---|---|---|---|---|
| 1 | MEDIUM | runtime (Playwright + CSP ADR-OPS-06) | `react-aria@3.53.1`, `usePress` (via `react-aria-components`, chunk `index-*.js`) | Au premier bouton monté, React Aria insère un `<style id="react-aria-pressable-style">` inline (`[data-react-aria-pressable]{touch-action: pan-x pan-y pinch-zoom}`). Avec `style-src 'self'`, il est **bloqué** et lève une violation CSP en console. La CSP fonctionne (aucun affaiblissement), mais : (a) le futur test E2E CSP et tout rapport de violation seront rouges, (b) sur mobile, le double-tap zoom n'est plus neutralisé sur les boutons, (c) risque qu'on « corrige » en ajoutant `'unsafe-inline'` à `style-src`, ce qui est **à refuser** | React Aria n'injecte rien si un élément portant l'id `react-aria-pressable-style` existe déjà. Créer `public/react-aria-pressable.css` avec la règle ci-dessus et ajouter dans `index.html` : `<link rel="stylesheet" id="react-aria-pressable-style" href="/react-aria-pressable.css">` (servi depuis `'self'`). Alternative moins robuste : hash `'sha256-38RhXrc7EdReTKsOm23ZPOCUgniTUUcjky8QOOrQx6o='` dans `style-src` (change à chaque version de React Aria). Ajouter le test E2E « aucune `securitypolicyviolation` » avec SEC-03a | haute (reproduit, source lue dans `usePress.mjs`) |
| 2 | LOW | manuel | `package.json` (`@react-three/drei` en dépendance prod), futur code `src/render/` | drei n'est pas importé (0 octet dans le bundle) mais reste installé avec ses dépendances transitives (`hls.js`, `@mediapipe/tasks-vision`, `@dimforge/rapier3d-compat`, `draco3d`…). Certains de ses helpers chargent depuis un CDN par défaut (`Environment preset` → githack, `useGLTF` → décodeur Draco sur gstatic, `Text` → polices distantes), ce que la CSP `connect-src 'self'` bloquerait | Soit retirer drei tant qu'il ne sert pas, soit ajouter une règle Semgrep/ESLint qui interdit `Environment` avec `preset`/`files` distants et impose un chemin local au décodeur Draco/KTX2 (ADR-3D-04) |
