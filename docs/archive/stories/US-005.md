En tant qu'utilisateur, je veux une interface claire en anglais (zone 3D, panneau d'objets, panneau de propriétés, alertes) afin de m'y repérer sans aide.
Critères d'acceptation :
- [x] Étant donné l'app, quand elle se charge, alors la mise en page (wireframe W2) affiche la scène plein viewport avec top bar, panneau gauche (onglets Desk / Objects), panneau droit (Properties puis Alerts) et astuce en pied, en panneaux flottants ; les deux panneaux latéraux sont repliables.
- [x] Tous les textes visibles sont en anglais et proviennent des fichiers i18n (aucun texte en dur dans les composants) ; `lang="en"` sur le document ; la structure permet d'ajouter une langue plus tard.
- [x] *(garde-fou i18n, revue US-003)* Le lint détecte aussi le texte en dur dans un ternaire, une expression logique (`&&`, `||`, `??`) et une concaténation : soit en adoptant `eslint-plugin-i18next/no-literal-string` (modes `jsx-text-only` + `jsx-attributes`), soit en étendant le sélecteur natif d'ADR-APP-10 aux `ConditionalExpression`, `LogicalExpression` et `BinaryExpression` ; cas couverts par `tests/unit/lint-rules.test.ts`.
- [x] Les composants respectent le design system (tokens générés depuis `docs/design/ui/tokens.css`, aucune couleur/taille en dur) et l'accessibilité WCAG 2.2 AA (contraste 4,5:1 texte / 3:1 éléments, focus visible non masqué, libellés, cibles ≥ 32 px, texte ≥ 14 px, reflow à 200 % de zoom, mise en page valide dès 1366×768).
- [x] Effet de verre : panneaux et barres flottants utilisent le verre à **86 % d'opacité minimum** (flou 24 px) ; fond **opaque de repli** (sans flou) quand `backdrop-filter` n'est pas supporté, quand `prefers-reduced-transparency: reduce`, ou quand la classe `.no-glass` est posée (option "Reduce transparency", voir US-025) ; l'interface reste identique, seul le flou disparaît. Les contrastes AA sont tenus sur le pire fond possible.
- [x] `prefers-reduced-motion: reduce` neutralise animations et transitions (durées à 0, pas d'effet d'appui, barre de chargement statique).
- [x] Le thème par défaut suit le système (`prefers-color-scheme`) ; thèmes clair et sombre fonctionnels.
- [x] Ordre de tabulation : top bar → panneau gauche → scène → panneau droit ; liens "Skip to 3D view" et "Skip to alerts" en tête.
- [x] **Inter auto-hébergée** : fichier `public/fonts/inter-latin-wght-normal.woff2` servi en same-origin (`font-src 'self'`, aucune requête tierce), `@font-face` avec `font-display: swap` et repli système, précharge dans `index.html` ; **licence SIL OFL 1.1 consignée** (`public/fonts/OFL.txt` + entrée dans `docs/design/3d/licences-assets.md`/`THIRD_PARTY_LICENSES`). Icônes Lucide (ISC, licence conservée) ; aucune police ni icône Apple.
- [x] Les états vide, chargement ("Loading 3D scene…", barre `role="progressbar"`, shell visible) et erreur / navigateur sans WebGL (W11) sont définis.
- [x] Le nom affiché « Deskfit » (`app.name` = "Deskfit", décision PO 29) est un mot-symbole texte (pas d'asset logo) ; titre de page « Deskfit - Plan your desk setup ».
- [x] *(suivi US-004, ux-designer ; texte validé par le PO)* L'état `failed` de la scène (hors WebGL indisponible) affiche le texte neutre : titre « The 3D view didn't load », corps « Something went wrong while starting it. Try again. If the problem continues, reload this page. », bouton "Try again", puis bouton "Reload page" **à partir du 2e échec consécutif** ; texte dans les fichiers i18n, test du texte exact et du `role="alert"`.
- [x] *(décisions PO 29, périmètre du shell)* Undo / Redo **ne sont pas rendus** jusqu'à US-019 (aucun bouton mort) ; le verdict vide affiche « Nothing to check yet » ; l'onglet "Objects" est visible avec l'état vide « No objects to add yet / The object library will appear here. » ; File, Help, "Saved in this browser" et "Alert settings" ne sont pas rendus.
- [x] *(messages d'import, dette US-003, rattachés à US-018)* `tooLarge` reste « This file is too large (1 MB max). Choose another file. » ; `tooManyObjects` devient « This setup has too many objects (50 max). Choose another file. » (UX-23, à vérifier dans US-018).
- [x] **Critères UX testables (ux-designer, `docs/design/ux/stories/US-005.md` §7, UX-1 à UX-22 ; UX-23 → US-018)** :
  - UX-1 À 1366×768 : scène plein viewport, top bar 56 px, deux panneaux flottants (248 et 312 px, marges 12 px), aucune barre de défilement de page ; chaque panneau défile en interne.
  - UX-2 Le `role="status"` « Nothing to check yet » est visible en haut à droite, de 320 à 1920 px CSS, panneaux repliés ou non, tiroir ouvert ou non, dans tous les états de la scène ; jamais icône seule ni rogné.
  - UX-3 Exactement un `banner`, un `main`, deux `complementary` nommés ("Desk and objects", "Properties and alerts"), un `h1`, pas de saut de niveau ; `lang="en"` ; titre de page défini.
  - UX-4 Les deux skip links sont les deux premiers arrêts de Tab, invisibles hors focus, non masqués au focus ; "Skip to 3D view" focalise le viewport ; "Skip to alerts" ouvre le panneau droit s'il est replié et focalise le titre "Alerts".
  - UX-5 Ordre de Tab : Skip to 3D view, Skip to alerts, bascule gauche, onglet sélectionné, contenu de l'onglet, viewport, Reset view, Top, Front, (Got it, Hide tip), bascule droite ; aucun piège, aucun `tabindex` positif, focus visible ≥ 3:1 jamais masqué. (Undo/Redo absents, décision 29.)
  - UX-6 Chaque bascule : `aria-expanded`, `aria-controls`, nom constant, cible ≥ 40 px ; le focus reste sur la bascule ; contenu replié retiré de Tab et de l'arbre d'accessibilité ; le choix survit au rechargement en mode large.
  - UX-7 (reformulé le 2026-11-01, [fiche UX US-007](../../design/ux/stories/US-007.md) §8) : ouvrir ou replier un panneau ne déplace ni l'orientation ni la cible de la caméra ; le dock suit la zone libre entre les panneaux et n'est jamais recouvert par un volet ouvert.
  - UX-8 À 1366×768 panneaux ouverts, après chargement et après "Reset view"/"Top"/"Front", le bureau entier est visible dans la zone libre (758 px) avec une marge ≥ 24 px de chaque côté (exigence graphics-engineer).
  - UX-9 Sous 1024 px CSS (dont 1366×768 à 200 %) : tiroirs fermés au chargement, un seul ouvert à la fois, Échap ferme et renvoie le focus à la bascule, top bar et verdict jamais recouverts ; à 320 px pas de défilement horizontal, aucune commande coupée.
  - UX-10 `tablist`/`tab`/`tabpanel` ; "Desk" sélectionné au chargement ; flèches gauche/droite changent d'onglet ; onglet actif distinct autrement que par la couleur.
  - UX-11 Textes des états vides (Verdict, Properties, Alerts, Objects) conformes au §6 de l'UX, sans lien ni bouton mort.
  - UX-12 Aucun élément "File", "Help", "Alert settings", "Saved…" ni crayon d'édition dans le DOM ; **Undo/Redo absents du DOM** (décision PO 29, à la place de « présents désactivés » de l'UX d'origine).
  - UX-13 Shell visible pendant "Loading 3D scene…" (`role="progressbar"`), panneaux utilisables, CLS ≈ 0 sur la zone de scène.
  - UX-14 État `failed` : titre et corps exacts dans `role="alert"`, focus sur le titre, "Try again" relance l'initialisation ; le texte ne contient ni "browser", "device", "support" ni "WebGL" ; pas de barre de vue ni d'astuce ; aucune exception non gérée.
  - UX-15 "Reload page" absent au 1er échec, présent et fonctionnel dès le 2e échec consécutif, absent pour `unsupported` et `contextLost`.
  - UX-16 `unsupported` et `contextLost` gardent exactement les textes d'US-004 ; `failed` n'affiche jamais le texte `unsupported`.
  - UX-17 Tous les textes viennent de `src/locales/en/` ; aucun libellé ne contient "orbit", "pan", "mesh" ou "camera".
  - UX-18 Verre ≥ 86 % avec repli opaque sans flou (sans `backdrop-filter`, `prefers-reduced-transparency`, `.no-glass`) ; contrastes ≥ 4,5:1 texte et ≥ 3:1 icônes/contours, clair et sombre ; texte ≥ 14 px ; cibles ≥ 32 px ; thème par défaut = système.
  - UX-19 Sous `prefers-reduced-motion: reduce`, repli/ouverture instantanés et barre de chargement statique.
  - UX-20 Info-bulle des bascules immédiate au focus clavier, ~400 ms au survol, Échap la ferme sans quitter le focus.
  - UX-21 Barre de vue et astuce centrées dans la zone libre, jamais sous un panneau à 1366 px, comportement d'US-004 conservé.
  - UX-22 Focus dans un panneau ou la top bar : 0, 1, 2, flèches, + et - ne déplacent pas la caméra.
