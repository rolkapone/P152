# UX — US-004 Scène 3D de base et caméra orbitale [UI][3D]

Périmètre : zone de scène du Studio (W2) + barre flottante de vue + astuce. Pas d'objets, pas de panneaux, pas de Snap (US-012). Textes d'interface en anglais, ton de `principes.md` (pas de jargon 3D : jamais "orbit", "pan", "mesh", "camera").

## 1. Parcours concerné
Parcours "premier setup" (`parcours.md`), étape "regarder son bureau" : Carol ouvre l'app -> voit "Loading 3D scene…" -> voit son bureau en studio clair -> comprend en 3 s qu'elle peut tourner/zoomer (astuce) -> tourne la vue, se perd -> "Reset view" (un clic) -> "Top" pour voir le plateau à plat. Alternative clavier / lecteur d'écran couverte en §5.

Justification : un seul élément d'interface ajouté (une barre de 3 boutons) + une astuce ; tout geste a un équivalent bouton ou clavier (principe 1 et 2.5.7).

## 2. Wireframes

### 2.1 Scène prête (état nominal, astuce visible)
```
┌─ 3D VIEWPORT (region "3D view", tabindex=0) ───────────────────────────────┐
│                                                                            │
│                                                                            │
│                  ______________________                                    │
│                 /_____________________/|      fond studio continu          │
│                 |   desk 140 x 70 cm   ||      ombres de contact douces    │
│                 |_____________________|/                                   │
│                  | |               | |                                     │
│                                                                            │
│                                                                            │
│  ┌──────────────────────────────────────────────────────────────────────┐  │
│  │ (i) Drag to turn the view, scroll to zoom, right-drag to move the    │  │  Astuce (verre)
│  │     view.                                          [ Got it ] [ X ]  │  │
│  └──────────────────────────────────────────────────────────────────────┘  │
│                   ┌────────────────────────────────────┐                   │
│                   │ [↺ Reset view]  [⬒ Top]  [▭ Front] │                   │  Barre de vue (verre, pill)
│                   └────────────────────────────────────┘                   │
└────────────────────────────────────────────────────────────────────────────┘
```
- Barre : bas-centre de la scène, role="toolbar" aria-label="View". Dans W2 l'astuce est dans une bande en bas du Studio ; pour US-004 (shell minimal), elle est un bandeau de verre au-dessus de la barre, dans la scène (US-005 pourra la déplacer dans la bande basse de W2 sans changer le texte).
- Icônes Lucide + libellé visible (pas d'icône seule) : Reset view = `rotate-ccw`, Top = vue de dessus, Front = vue de face. Cible >= 32 px de haut, espacement >= 8 px.
- Astuce : "Got it" (masque et mémorise) et "X" (aria-label "Hide tip", même effet). Un seul des deux suffit : garder uniquement **"Got it"** si l'espace manque à 1366 px ; décision par défaut : les deux (X = habitude, "Got it" = libellé explicite).

### 2.2 Chargement
```
┌─ 3D VIEWPORT ──────────────────────────────────────────────┐
│                                                            │
│                     (fond studio uni, token --scene-bg)    │
│                  Loading 3D scene…                         │
│                  [██████░░░░░░░░░░░░]  role="progressbar"  │
│                                                            │
│   (barre de vue absente tant que la scène n'est pas prête) │
└────────────────────────────────────────────────────────────┘
```
Zone `aria-live="polite"` : "Loading 3D scene…" puis "3D view ready. Desk 140 by 70 cm." Sous reduced-motion la barre de progression est statique. Pas de saut de mise en page à l'arrivée du canvas (même taille réservée).

### 2.3 Barre de vue : états des boutons
```
Repos        [↺ Reset view]  [⬒ Top ]  [▭ Front ]
Survol       fond surface-hover ; info-bulle après 400 ms
Focus clavier anneau 2 px accent (+ halo clair/sombre, contraste >= 3:1), jamais masqué ; info-bulle aussi au focus
Vue active   [⬒ Top ✓]   fond accent-subtle opaque + coche + contour 2 px (jamais la couleur seule), aria-pressed="true"
Transition   boutons actifs inchangés pendant les 480 ms ; aria-pressed bascule au début de la transition
Désactivé    aucun (jamais désactivés ; Reset view sur la vue par défaut reste cliquable)
```
```
Info-bulle (au-dessus du bouton, 14 px, fond inversé) :
  Reset view : "Reset view (0)"     Top : "View from above (1)"     Front : "View from the front (2)"
```
Règles d'état : Reset view n'est pas un bouton à bascule (pas d'aria-pressed). Top et Front : exactement un actif au plus ; l'état actif est retiré dès que l'utilisateur tourne/zoome/déplace la vue (la vue n'est plus celle du bouton). Après Reset view, aucun bouton n'est pressé.

### 2.4 Astuce masquée
```
┌─ 3D VIEWPORT ───────────────────────────────┐
│                  (scène)                    │
│            [↺ Reset view] [⬒ Top] [▭ Front] │
└─────────────────────────────────────────────┘
```
Le masquage est mémorisé dans le navigateur (préférence locale, pas dans le setup) ; la barre ne bouge pas. Pour la rouvrir : bouton `?` de la barre du haut (Help, US-025). Tant que Help n'existe pas : l'astuce reste masquée (décision PO à confirmer, voir §8).

### 2.5 WebGL indisponible
```
┌─ 3D VIEWPORT ───────────────────────────────────────────────┐
│                                                             │
│            (!)  The 3D view can't start                     │
│   Your browser or device doesn't support 3D graphics        │
│   (WebGL 2). Try updating your browser, turning on          │
│   hardware acceleration, or opening Deskfit in Chrome,      │
│   Edge, Firefox or Safari.                                  │
│                  [ Try again ]                              │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```
role="alert" (une fois), message en bandeau opaque (pas de verre), pas de barre de vue ni d'astuce. "Try again" relance l'initialisation ; le focus va sur le titre du message à l'apparition. Même écran si le contexte WebGL est perdu en cours d'usage, avec le titre "The 3D view stopped" et le corps "The graphics connection was lost. Try again to restore your desk." (le setup n'est pas perdu).

## 4. Comportements de la vue (point de vue utilisateur)
| Geste | Effet | Limites perçues |
|---|---|---|
| Glisser, clic gauche sur le vide | La vue tourne autour du bureau | Jamais sous le plateau/sol (on ne regarde jamais le bureau "par en dessous") ; l'angle reste dans le studio (pas de vue vers l'extérieur de la cyclo, azimut limité) |
| Molette / pavé tactile | Zoom avant/arrière, centré sur le bureau | Distance min : on ne traverse jamais le bureau ni ses objets futurs ; distance max : le bureau reste lisible (>= env. 25 % de la largeur de la scène) |
| Glisser, clic droit | Déplace la vue | Le bureau ne sort jamais complètement du cadre (au moins une partie reste visible) |
| Reset view | Retour à la vue par défaut (3/4 haut, bureau centré, cadré avec marge) | Toujours disponible |
| Top | Vue de dessus, plateau à plat, cadré entier avec marge, orientation stable (bord arrière en haut) | -- |
| Front | Vue de face, à hauteur d'yeux au-dessus du plateau, cadré entier | -- |
- Valeurs numériques (distances, angles, bornes de pan) : à fixer par le graphics-engineer ; l'UX exige les propriétés ci-dessus, vérifiables par test.
- Transitions de vue (Reset/Top/Front) : 480 ms, courbe `in-out`. Si l'utilisateur agit pendant la transition (glisser, molette, autre bouton), la transition est interrompue et la nouvelle action prend la main sans à-coup.
- Zoom limité : au-delà d'une borne, rien ne se passe (pas de rebond ni de message).
- Pas d'inertie longue : la vue s'arrête <= 200 ms après le relâchement (confort, pas de vertige).
- Le curseur indique l'action : `grab` sur le vide au survol, `grabbing` pendant la rotation, `move` pendant le déplacement.
- Entrées en Pointer Events ; le menu contextuel du navigateur est supprimé sur la scène pour le clic droit glissé.
- `prefers-reduced-motion: reduce` : Reset/Top/Front sautent directement à la vue (0 ms) ; plus d'inertie ; la barre de chargement est statique ; l'astuce apparaît sans animation.

## 5. Clavier et lecteur d'écran
**Ordre de tabulation (dans la scène)** : zone de scène (viewport, `tabindex=0`, `role="application"` évité ; utiliser `role="group"` aria-label "3D view of your desk. Use arrow keys to turn the view, plus and minus to zoom.") -> Reset view -> Top -> Front -> (astuce) Got it -> Hide tip. Position globale : après la barre du haut et le panneau gauche, avant le panneau droit (W2). Un lien "Skip to 3D view" (US-005) cible la zone de scène.

**Alternative clavier au glisser (2.5.7), actives quand le viewport a le focus et que rien n'est sélectionné :**
| Touche | Effet |
|---|---|
| Flèches gauche/droite | Tourner la vue de 15° |
| Flèches haut/bas | Incliner la vue de 10° (dans les bornes) |
| + / - (ou =, _) | Zoom avant / arrière (pas de 10 %) |
| Maj + flèches | Déplacer la vue (pas de 5 % de la largeur du bureau) |
| 0 / 1 / 2 | Reset view / Top / Front |
Les raccourcis à une touche (0, 1, 2) ne sont actifs que lorsque le viewport a le focus (jamais dans un champ de saisie ni globalement : WCAG 2.1.4). Les touches de la scène ne piègent pas le focus : Tab/Maj+Tab sortent normalement (2.1.2). Quand US-013 introduira la sélection, les flèches serviront à déplacer l'objet sélectionné ; la vue sera alors pilotée par Alt+flèches (à noter dans US-013).

**Annonces `aria-live="polite"`** (une zone unique, visuellement masquée, une annonce par action, regroupées si l'utilisateur répète) :
- "Top view." / "Front view." / "View reset." au clic ou raccourci ;
- pour les gestes continus (flèches, +/-) : annonce unique après 600 ms d'inactivité, ex. "View turned 30 degrees right." / "Zoomed in." / "Zoom limit reached." (uniquement si la borne est atteinte via le clavier) ;
- aucune annonce pendant un glisser souris.
Les boutons ont `aria-label` = libellé visible, `aria-pressed` sur Top/Front ; la barre a `role="toolbar"` et flèches gauche/droite entre boutons non requises (Tab suffit, trois boutons).

**Focus** : l'anneau est toujours visible (verre inclus), jamais caché par l'astuce ou la barre. Quand l'astuce est masquée au clavier, le focus passe sur Reset view. Lors de l'apparition du message WebGL, le focus va sur son titre.

## 7. Critères UX testables (à ajouter à la story par le scrum-master)
1. Au chargement, "Loading 3D scene…" est visible avec `role="progressbar"` ; à la fin, "3D view ready. Desk 140 by 70 cm." est annoncé dans la zone `aria-live="polite"` et le canvas occupe la même place sans décalage de mise en page.
2. La barre de vue (`role="toolbar"`, `aria-label="View"`) affiche, avec libellés visibles et icônes, "Reset view", "Top", "Front" ; chaque bouton mesure >= 32 px de haut (jamais < 24 px) et sa zone de clic est séparée de >= 8 px de la suivante.
3. Tab atteint dans l'ordre : scène -> Reset view -> Top -> Front -> "Got it" -> "Hide tip" ; aucun piège clavier ; l'anneau de focus est visible (contraste >= 3:1) sur fond clair et sombre, et n'est pas masqué par l'astuce.
4. Chaque bouton de vue affiche une info-bulle après ~400 ms au survol **et** au focus clavier (textes du §6) ; Échap la ferme sans quitter le focus.
5. Après clic ou Entrée/Espace sur Top, `aria-pressed="true"` sur Top uniquement, coche + contour visibles (pas la couleur seule) ; annonce "Top view." ; après un glisser, un zoom ou Reset view, plus aucun bouton n'est pressé.
6. Reset view ramène exactement la vue par défaut depuis n'importe quelle vue, y compris après des limites atteintes ; Top montre le plateau entier, à plat, bord arrière en haut ; Front montre le bureau entier de face.
7. Clic gauche glissé sur le vide tourne la vue ; molette zoome ; clic droit glissé déplace la vue, sans menu contextuel du navigateur ; la vue ne passe jamais sous le plateau/sol ; le zoom ne traverse jamais le bureau ; au zoom max (éloigné) le bureau reste visible et le déplacement ne le sort jamais complètement du cadre.
8. Au clavier, viewport focalisé : flèches tournent, + / - zooment, Maj+flèches déplacent, 0/1/2 activent Reset/Top/Front ; ces touches n'agissent pas hors du viewport ; une annonce unique est émise après 600 ms d'inactivité, aucune pendant un glisser souris.
9. Une transition de vue dure 480 ms (courbe `in-out`) ; une action de l'utilisateur pendant la transition l'interrompt sans à-coup.
10. Avec `prefers-reduced-motion: reduce`, Reset/Top/Front sautent à la vue sans animation, sans inertie ; la barre de chargement est statique.
11. L'astuce "Drag to turn the view, scroll to zoom, right-drag to move the view." est visible à la première visite ; "Got it" ou "Hide tip" la masque, le focus passe sur Reset view, et elle ne réapparaît pas après rechargement.
12. Barre et astuce sont en verre >= 86 % d'opacité avec repli opaque (sans `backdrop-filter`, avec `prefers-reduced-transparency`) ; texte >= 4,5:1 et icônes >= 3:1 sur studio clair et sombre ; texte >= 14 px.
13. Si WebGL 2 est indisponible, le message "The 3D view can't start" (role="alert", focus sur le titre) et "Try again" remplacent la scène ; aucune barre de vue ; aucune exception non gérée en console ; "Try again" relance l'initialisation.
14. L'interface de la scène reste utilisable à 200 % de zoom navigateur et à 1366×768 : la barre ne recouvre pas le bureau au cadrage par défaut ; l'astuce reste lisible sans masquer la barre.
15. Aucun libellé visible, info-bulle ou annonce ne contient "orbit", "pan", "mesh" ou "camera".
