# UX — US-005 Shell de l'application en anglais [UI]

Périmètre : la charpente du Studio (W2) et les états système (W11). On livre une coque **honnête** : chaque élément visible fait quelque chose ou affiche un état vide expliqué ; aucun bouton mort. Textes d'interface en anglais (`src/locales/en/`), documents en français. Ton de `principes.md` : pas de jargon 3D, pas d'accusation, pas de pronom.

## 0. Livré par US-005 ou simple emplacement prévu

Règle (architecture-info.md) : une fonction future n'apparaît à l'écran que lorsqu'elle existe. Un bouton qui ne fait rien est un piège pour tous, et pire pour un lecteur d'écran.

Écrans justifiés : 1 écran de travail (Studio) + 1 écran système (états de la scène). Aucune modale ni page ajoutée.

## 1. Parcours concerné
Parcours « premier setup » (`parcours.md`), étape 0 : Carol ouvre l'app -> voit **tout de suite** la structure (barre, panneaux, scène qui charge) au lieu d'un écran blanc -> comprend où est le verdict -> la scène arrive -> elle peut replier un panneau pour voir son bureau en grand. Cas d'erreur : la 3D ne démarre pas -> message clair, bouton "Try again", le reste de l'interface reste utilisable. Parcours clavier : skip link -> panneau -> scène.

- Ordre horizontal et DOM : top bar, panneau gauche, scène (`main`), panneau droit.
- Top bar, de gauche à droite : mot-symbole, nom du setup (tronqué avec `…` et `title` si long), Undo, Redo, [emplacement File], **verdict**, [emplacement Help]. Le verdict est calé à droite (juste avant l'emplacement Help) pour rester au même endroit quand File et Help arriveront (3.2.3).
- Les bascules « replier » `[«]` / `[»]` sont le premier élément de chaque panneau (même DOM, même place replié ou non).
- Marges 12 px, rayons et verre : design system §5 et §9. Largeurs 248 / 312 (DS §9). Zone libre à 1366 px : 1366 - 12 - 248 - 12 - 12 - 312 - 12 = **758 px**.
- Défilement : la page ne défile jamais ; chaque panneau défile en interne ; la barre du haut ne défile pas.

### 2.2 Repli des panneaux et petits écrans
```
A. Large (>= 1024 px CSS), gauche repliée         B. Large, les deux repliées
┌ TOP BAR ───────────────────────────────┐        ┌ TOP BAR ───────────────────────────────┐
│ P152 My desk setup ↶ ↷   ( verdict )   │        │ P152 My desk setup ↶ ↷   ( verdict )   │
│ [»]                          ┌ RIGHT ┐ │        │ [»]                                [«] │
│ (bouton 40 px,               │       │ │        │                                        │
│  verre, icône panel-left)    └───────┘ │        │   scène sur toute la largeur           │

C. Étroit (< 1024 px CSS, ou 1366 px à 200 % de zoom = 683 px CSS) : tiroirs, fermés par défaut
┌ TOP BAR ───────────────────────────┐          Tiroir ouvert (un seul à la fois, recouvre la scène)
│ P152 My desk setup ↶ ↷  (verdict)  │          ┌ TOP BAR ───────────────────────────┐
│ [»]                            [«] │          │ …                                  │
│                                    │          │ [«] ┌ DESK AND OBJECTS ──────────┐ │
│          scène                     │          │     │ contenu du panneau         │ │
│   [Reset view] [Top] [Front]       │          │     │ (largeur max 360 px, ou    │ │
└────────────────────────────────────┘          │     │ 100 % - 24 px)             │ │
                                                └─────┴────────────────────────────┘
```
Règles :
1. **Large (>= 1024 px CSS de large)** : les deux panneaux sont ouverts par défaut et peuvent être repliés indépendamment ; le choix est mémorisé (préférence locale, pas dans le setup). Panneau replié = seul son bouton reste (40 px, verre), à la même position.
2. **Étroit (< 1024 px CSS)**, ce qui inclut **1366×768 à 200 % de zoom** (683×384 px CSS) : les panneaux sont des **tiroirs**, **fermés au chargement**, jamais mémorisés ouverts. Ouvrir un tiroir ferme l'autre. Un tiroir ouvert recouvre la scène, ne recouvre jamais la top bar (donc le verdict reste visible) et défile en interne. Non modal : la scène derrière reste atteignable après Tab ; Échap ferme le tiroir quand le focus est dedans et renvoie le focus à sa bascule.
3. Le **focus ne bouge pas** quand on déplie ou replie (modèle « disclosure ») : il reste sur la bascule ; le contenu replié est retiré de l'ordre de tabulation et de l'arbre d'accessibilité (`inert` / `hidden`).
4. **Replier ou ouvrir un panneau ne déplace jamais la caméra** (pas de saut sous les yeux de l'utilisateur). Le cadrage tient compte des panneaux ouverts seulement quand il est calculé : au chargement, "Reset view", "Top", "Front" et changement de bureau (US-006). **Exigence pour le graphics-engineer** : le bureau entier, avec marge, tient dans la zone libre (758 px à 1366 px de large panneaux ouverts), pas dans le viewport entier (voir UX-8).
5. Reflow (1.4.10) : à 320 px CSS de large (400 % de zoom à 1280 px), pas de défilement horizontal de la page ; la top bar passe à la ligne si nécessaire (le verdict descend sur une 2e ligne plutôt que d'être coupé ou masqué) ; le nom du setup se tronque.
6. Hauteur faible (200 % : 384 px CSS) : les panneaux et tiroirs défilent ; la barre de vue et l'astuce restent comme en US-004 (UX-14 de US-004) ; ils ne passent jamais sous un tiroir ouvert sans qu'on puisse fermer ce dernier.
7. Animation de repli : translation + fondu 320 ms (`slow`, `out`), 0 ms sous `prefers-reduced-motion`.

### 2.3 Zone de scène : barre de vue et astuce
Inchangées par rapport à US-004 (§2.1 de `stories/US-004.md`) sauf la position : le dock (barre de vue + astuce) est centré dans la **zone libre entre les panneaux** (pas dans le viewport entier), donc jamais sous un panneau. Quand un panneau est replié, le dock reste où il est (même règle que la caméra, point 4 : pas de mouvement spontané) et ne se recentre qu'au prochain chargement de page. Le texte de l'astuce ne change pas.

### 2.4 États de la scène dans le shell (W11 affiné)
Dans tous les cas la top bar, le verdict et les deux panneaux restent affichés et utilisables.
```
Chargement (status "loading")                      Prête
┌─ zone de scène ────────────────────┐            voir 2.1
│        Loading 3D scene…           │
│        [██████░░░░░░░░░░]          │  role="progressbar" (statique en reduced motion)
│ (pas de barre de vue ni d'astuce)  │
└────────────────────────────────────┘

WebGL 2 absent ("unsupported", inchangé de US-004)   Échec de chargement ("failed", NOUVEAU texte neutre)
┌────────────────────────────────────┐              ┌────────────────────────────────────┐
│ (!) The 3D view can't start        │              │ (!) The 3D view didn't load        │
│ Your browser or device doesn't     │              │ Something went wrong while         │
│ support 3D graphics (WebGL 2). Try │              │ starting it. Try again. If the     │
│ updating your browser, turning on  │              │ problem continues, reload this     │
│ hardware acceleration, or opening  │              │ page.                              │
│ this page in Chrome, Edge, Firefox │              │ [ Try again ]                      │
│ or Safari.                         │              │ [ Reload page ]  <- 2e échec seul. │
│ [ Try again ]                      │              └────────────────────────────────────┘
└────────────────────────────────────┘

Contexte perdu ("contextLost", inchangé)
│ (!) The 3D view stopped │ The graphics connection was lost. Try again to restore your desk. │ [ Try again ]
```
- Carte opaque (pas de verre), `role="alert"`, focus sur le titre (`h2`, `tabindex=-1`) à chaque nouvelle tentative (carte remontée par `attempt`, comme aujourd'hui), pas de barre de vue ni d'astuce.
- **Pourquoi un texte distinct pour `failed`** : aujourd'hui `failed` (échec de chargement du code 3D, erreur au démarrage) affiche « The 3D view can't start / Your browser or device doesn't support 3D graphics ». C'est faux et accusateur : le navigateur n'y est pour rien. Le nouveau texte décrit un incident, pas une incompatibilité, et dit quoi faire.
- **Pourquoi "Reload page" à partir du 2e échec** : un chunk JavaScript dont le chargement a échoué reste en échec dans le navigateur ; "Try again" peut donc échouer en boucle. Au 2e échec consécutif (`attempt >= 1`), un second bouton secondaire "Reload page" (recharge le document) apparaît sous "Try again". Pas de bouton supplémentaire au 1er échec (un seul choix, pas de bruit). Le setup en mémoire n'est pas touché par "Try again".
- `unsupported` : "Reload page" n'est pas proposé (recharger ne change rien) ; texte et comportement de US-004 conservés.

### 2.5 Premier affichage et JavaScript désactivé
- Avant l'hydratation, `index.html` affiche un fond neutre aux couleurs du thème (pas de flash blanc en sombre) ; pas d'écran blanc prolongé : le shell apparaît avant la 3D (chunk 3D en `lazy()`).
- `<noscript>` : « Turn on JavaScript to use this app. » (texte statique anglais, hors i18n car sans JavaScript).
- `<title>` : « {nom de l'app} - Plan your desk setup » (2.4.2).

## 4. Landmarks, titres et ordre de tabulation

| Zone | Élément | Landmark / rôle | Nom |
|---|---|---|---|
| Tout en haut | 2 liens | -- | "Skip to 3D view", "Skip to alerts" |
| Top bar | `<header>` | banner | (mot-symbole en `h1`) |
| Panneau gauche | `<aside>` | complementary | aria-label "Desk and objects" |
| Scène | `<main>` | main | (le viewport garde son nom US-004 : "3D view of your desk. …") |
| Panneau droit | `<aside>` | complementary | aria-label "Properties and alerts" |
| Properties / Alerts | `<section>` | region (via titre) | `aria-labelledby` du `h2` |
| Verdict | -- | status | texte visible |

Titres : `h1` mot-symbole ; `h2` : titre de chaque onglet actif/section ("Desk", "Properties", "Alerts"), titres des cartes d'erreur (US-004). Pas de saut de niveau.

**Ordre de tabulation** (identique à l'ordre du DOM, aucun `tabindex` positif) :
1. Skip to 3D view -> 2. Skip to alerts
3. Nom du setup (non focalisable à US-005, texte) ; Undo et Redo **désactivés ne reçoivent pas le focus** ; verdict non focalisable
4. Bascule du panneau gauche -> onglet Desk/Objects sélectionné -> contenu du panneau (US-006 : le groupe de bureaux)
5. Scène (viewport) -> Reset view -> Top -> Front -> Got it -> Hide tip (ordre US-004)
6. Bascule du panneau droit -> contenus focalisables (aucun à US-005)
- "Skip to 3D view" met le focus sur le viewport (`tabindex=0` existant). "Skip to alerts" ouvre le panneau droit s'il est replié/en tiroir puis met le focus sur le titre "Alerts" (`tabindex=-1`).
- Les skip links sont visibles au focus : pastilles opaques en haut à gauche, au-dessus de la top bar, anneau de focus visible, jamais masquées (2.4.11).
- Les touches de la scène (flèches, +/-, 0/1/2) n'agissent que si le viewport a le focus (inchangé, WCAG 2.1.4). Aucun nouveau raccourci d'une touche.

### 6.1 Messages d'import à valider (dette US-003, repris par US-018)
Ces messages s'afficheront au moment de l'import (bandeau d'erreur ou message sous le sélecteur, US-018). Les autres codes d'erreur gardent leur texte actuel (« This file isn't a valid setup. Choose another file. », volontairement unique : on ne révèle rien du contenu du fichier).

| Code | Texte actuel | Texte validé par l'ux-designer |
|---|---|---|
| `tooLarge` | `This file is too large (1 MB max). Choose another file.` | **inchangé**. La limite réelle est 1 Mio (1 048 576 octets). « MB » est ce que Windows et macOS affichent à l'utilisateur ; on ne dit jamais « Mio/MiB » (jargon). Tout fichier refusé dépasse 1 048 576 octets, donc dépasse bien « 1 MB » : le message n'est jamais contredit par la taille affichée. |
| `tooManyObjects` | `This setup has more than 50 objects. Choose another file.` | **`This setup has too many objects (50 max). Choose another file.`** : même forme que `tooLarge`, donne la limite comme règle de l'app et non comme constat. |
Les deux restent des messages courts, sans accusation, avec une action ("Choose another file"). Affichage : `role="alert"`, focus sur le message ou le sélecteur de fichier (à préciser dans la story US-018).

## 7. Critères UX testables (à ajouter à la story par le scrum-master)

1. **Structure** : à 1366×768, le Studio affiche la scène sur tout le viewport, la top bar (56 px) et deux panneaux flottants (248 et 312 px, marges 12 px) ; la page n'a aucune barre de défilement ; chaque panneau défile en interne si besoin.
2. **Verdict toujours visible** : l'élément `role="status"` "Nothing to check yet" est visible en haut, à droite des commandes, à toutes les largeurs de 320 px à 1920 px CSS, panneaux repliés ou non, tiroir ouvert ou non, et dans tous les états de la scène (chargement, prête, `unsupported`, `failed`, `contextLost`). Il n'est jamais réduit à une icône seule ni rogné.
3. **Landmarks** : le document a exactement un `banner`, un `main`, deux `complementary` nommés ("Desk and objects", "Properties and alerts"), un `h1` et pas de saut de niveau de titre ; `lang="en"` ; titre de page défini.
4. **Skip links** : ce sont les deux premiers arrêts de Tab, invisibles hors focus, visibles et non masqués au focus. "Skip to 3D view" met le focus sur le viewport ; "Skip to alerts" ouvre le panneau droit s'il est replié ou en tiroir et met le focus sur le titre "Alerts".
5. **Ordre de tabulation** : Skip to 3D view -> Skip to alerts -> bascule gauche -> onglet sélectionné -> contenu de l'onglet -> viewport -> Reset view -> Top -> Front -> (Got it -> Hide tip) -> bascule droite ; Undo et Redo désactivés ne sont pas atteints ; aucun piège clavier ; aucun `tabindex` positif ; l'anneau de focus est visible (>= 3:1) sur chaque élément et jamais masqué par un panneau.
6. **Repli des panneaux** : chaque bascule a `aria-expanded` et `aria-controls`, un nom accessible constant, une cible >= 40 px ; au clic ou Entrée/Espace, le panneau se replie, le focus reste sur la bascule, le contenu replié n'est plus atteignable par Tab ni exposé aux lecteurs d'écran ; le choix survit à un rechargement en mode large.
7. **Pas de saut de caméra** : replier ou ouvrir un panneau ne modifie pas la position de la caméra ni du dock.
8. **Cadrage dans la zone libre** : à 1366×768, panneaux ouverts, après le chargement et après "Reset view", "Top" ou "Front", le bureau entier est visible dans l'espace entre les panneaux, avec une marge >= 24 px de chaque côté.
9. **Petits écrans** : sous 1024 px CSS de large (dont 1366×768 à 200 % de zoom), les panneaux sont des tiroirs fermés au chargement ; ouvrir l'un ferme l'autre ; Échap ferme le tiroir et ramène le focus sur sa bascule ; la top bar et le verdict ne sont jamais recouverts ; à 320 px CSS il n'y a pas de défilement horizontal de la page et aucune commande n'est coupée.
10. **Onglets** : `tablist` / `tab` / `tabpanel` ; "Desk" est sélectionné au chargement ; les flèches gauche/droite changent d'onglet ; l'onglet sélectionné se distingue par autre chose que la couleur (graisse + contour ou soulignement).
11. **États vides** : les textes du §6 pour Verdict, Properties, Alerts et Objects sont affichés à l'ouverture, à l'identique, sans lien ni bouton mort.
