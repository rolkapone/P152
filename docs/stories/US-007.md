# US-007 — Dimensions personnalisées du bureau  [UI] [Should | 3 pts]

> Statut : **TODO** (Sprint 3) · Voie : **STANDARD** (saisie utilisateur bornée, aucun fichier ni lien externe) · 3 pts · Should · Epic C — Bureau. Index : [backlog](../backlog.md). Dette rattachée : [dette.md](../dette.md).

En tant qu'utilisateur, je veux saisir largeur, profondeur et hauteur de mon bureau afin de refléter exactement le mien.
Critères d'acceptation :
- [ ] Étant donné un bureau sélectionné, quand je déplie "Custom size" (replié par défaut) et saisis des valeurs, alors le bureau est redimensionné en temps réel.
- [ ] Les valeurs hors bornes sont refusées avec un message sous le champ, relié par `aria-describedby`, ex. "Enter a width between X and Y mm." (bornes = celles du catalogue, voir question PO) ; l'ancienne valeur est conservée et le focus revient au champ en erreur.
- [ ] Les champs sont des NumberField avec libellé visible, suffixe "mm", pas 10 mm (Maj 1, Ctrl 100).
- [ ] Les alertes sont recalculées après modification.
Notes techniques / dépendances : dépend de US-006. Wireframes W3 et W7. Bornes (décision PO 30) : rectangulaire 800–2400 × 500–1000 × 600–1300 mm ; **le bureau d'angle n'a pas de "Custom size"** (angle 1200–2400 × 1000–2000 mm, hors saisie), à rouvrir si le PO le demande.
Critères ajoutés au planning du Sprint 3 (dette US-005 / US-006, 0 pt) :
- [ ] `deskSpec` compare tous les params (hauteur comprise) : un 1400×700 de hauteur différente n'est plus « Standard desk » ; test dédié.
- [ ] « cm » ne passe plus à la ligne dans la colonne de 235 px à 1366 et 1024 px (QA, capture).
- [ ] Test négatif pour `preset.name` (`src/core/catalog/schema.ts`) : vide, 81 caractères, clé de langue en trop.
- [x] UX-7 **de US-005** reformulé par l'ux-designer (dock et zone libre à l'ouverture d'un volet, arbitrage avec UX-21) avant le code ; reporté dans la fiche archivée US-005 (`docs/archive/stories/US-005.md`). Les UX-n de "Custom size" sont ci-dessous.

Critères UX (ux-designer, [fiche UX](../design/ux/stories/US-007.md) §7 ; décision 56) :
- [ ] UX-1 Une ligne radio "Custom size" termine la liste ; la choisir ouvre Width, Depth, Height préremplis avec le bureau courant, sans changer la scène.
- [ ] UX-2 Chaque champ : libellé visible, unité "cm" et équivalent mm visibles ; "cm" reste sur une ligne dans 235 px à 1366 et 1024 px.
- [ ] UX-3 Flèches/stepper appliquent à chaque pas (1 cm ; Maj 0,1 ; Ctrl 10) ; la saisie s'applique à Entrée ou à la sortie du champ ; une seule recalcul d'alertes par validation.
- [ ] UX-4 Hors bornes ou vide : scène inchangée, message exact (fiche UX §5) relié par `aria-describedby`, `aria-invalid`, icône + texte + bordure ; focus conservé à Entrée, jamais forcé à la sortie par Tab.
- [ ] UX-5 Échap restaure la dernière valeur valide ; les bornes proviennent du catalogue (aucun nombre en dur).
- [ ] UX-6 Ligne Custom size active : contour 2 px, coche, fond `accent-subtle`, `aria-checked` ; reste active même si les valeurs égalent un modèle ; résumé en cm, mm et hauteur.
- [ ] UX-7 Bureau d'angle actif : ligne désactivée avec `Rectangular desks only`, aucun champ.
- [ ] UX-8 Un 1400 × 700 de hauteur différente n'est pas « Standard » (résumé et ligne active corrects).
- [ ] UX-9 Annonce regroupée à 400 ms, une seule après une rafale de 5 pas ; erreur annoncée une fois.
- [ ] UX-10 Retour à un modèle : champs refermés, valeurs personnalisées gardées pour le retour ; focus resté sur la ligne.
- [ ] UX-11 Bureau entier visible dans la zone libre (marge ≥ 24 px) à 1366×768 après validation.
- [ ] UX-12 Texte ≥ 14 px, cibles ≥ 32 px, contrastes AA clair et sombre, reduced motion respecté ; textes identiques à `src/locales/en/`.
